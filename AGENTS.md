# Robo Study

Robo Study — «Робот ОП ИРНИТУ», курсовой проект по роботизации сбора и преобразования документов образовательных программ. Репозиторий — `Qcsteeven/robo-study`. Основная ветка исходного кода — `main`. Сведения ниже проверены по состоянию на 17 ноября 2026 года. Снимки данных и результаты отдельных прогонов помечены датой.

## С чего начать работу

- Откройте существующий клон в WSL. Выполните `git status --short --branch` и проверьте `origin`, прежде чем обновлять ветку. Сохраните уже имеющиеся правки. Обновляйте `main` через fast-forward, когда это возможно.
- Перед запуском проверьте [каталог приложения](http://127.0.0.1:8000/programs) и владельца порта 8000. Если запуск уже идёт, проверьте его статус до перезапуска сервера.
- Отличайте данные рабочего приложения от демонабора, временных БД тестов и опубликованного статического снимка. Любые числа по охвату сверяйте с тем экземпляром, который проверяете.
- Рабочие PDF и SQLite лежат в `data/`. Храните `.env`, ключи, журналы, резервные копии, `data.demo-backup/` и `server.log` локально. Перед коммитом сверяйте состав индексированных файлов.
- Описание технологии и исходные команды также приведены в [README.md](README.md). Проверяйте датированные утверждения README по текущему коду, БД или манифесту экспорта.

## Запуск приложения

### Локальная работа в WSL

На рабочем стенде использовались Ubuntu 24.04, Python 3.12 и установленное окружение `.venv`. Запускать из корня репозитория:

```bash
.venv/bin/python -m robot_op serve --host 127.0.0.1 --port 8000
```

Каталог доступен по адресу [127.0.0.1:8000/programs](http://127.0.0.1:8000/programs). HTTP 200 на каталоге и на странице сохранённой ОП подтверждает, что приложение отвечает с данными. Для проверки после изменения кода полезны страницы [ИСОИУ](http://127.0.0.1:8000/op/09.03.01-isoiu-2026-och) и [ЦППМ](http://127.0.0.1:8000/op/09.04.02-cpp-2026-och).

Для нового окружения установите зависимости из [requirements-dev.txt](requirements-dev.txt). Для сканов нужен Tesseract 5 с языками `rus` и `eng`, для демодокументов нужен шрифт DejaVu. Базовая конфигурация находится в [config/robot.toml](config/robot.toml). Локальные параметры переопределяются через `.env` и переменные `ROBOT_*`. По умолчанию локальный режим использует `data/robot.db`.

- Демо-режим запускается командой `python -m robot_op serve --demo`. Используйте отдельный каталог данных и отдельную БД для демонстраций, которые могут записывать результаты.
- Команда `python -m robot_op pages` пересобирает сохранённые страницы ОП из итоговых JSON. Она обновляет представления в БД без скачивания PDF. Параметр `--refresh-teachers` заново извлекает распределение преподавателей и персональные ссылки ИРНИТУ.
- Команда `python -m robot_op run <уровень> <ключи программ>` относится к последнему году набора уровня. Для архивного набора используйте выбор года и программы в веб-каталоге. Запуск без ключей выбирает весь уровень.
- При запросе повторной обработки сначала определите точные программы и год набора. Перед операциями с рабочей БД проверьте очередь и сделайте резервную копию. Для проверок пользуйтесь временной БД.

### Развёртывание на сервере

Основной серверный режим по ТЗ — [Docker Compose](docker-compose.yml). В созданном окружении выполните `docker compose up -d --build`. Сервис `app` запускает FastAPI, Uvicorn и Tesseract, сервис `db` — PostgreSQL 16. Подготовьте `.env` по [.env.example](.env.example) и задайте параметры конкретного стенда. В Compose PDF и рабочие файлы лежат в томе `robot-data`, PostgreSQL использует `pgdata`.

- Профиль `llm` добавляет Ollama. Внешние API и GigaChat также поддерживаются. Выбор поставщика задаёт `ROBOT_LLM_PROVIDER`. Ключи хранятся в окружении сервера.
- Профиль `https` включает Nginx. Конфигурация в [deploy/nginx.conf](deploy/nginx.conf), сертификаты размещаются в `deploy/certs/`.
- Для переноса уже обработанных программ из локальной SQLite нужны перенос записей в целевую БД и доступность сохранённых PDF в целевом хранилище. Сам Compose поднимает отдельную PostgreSQL. После переноса проверьте ссылки на документы по штатным маршрутам.

## Как работает обработка

Основные каталоги исходников:

| Место | Назначение |
|---|---|
| [robot_op/web/](robot_op/web/) | FastAPI, Jinja, стили, каталог и страницы программ |
| [robot_op/robot/](robot_op/robot/) | Запросы к ИРНИТУ, очередь, обработка документов, характеристики LLM и сборка страниц |
| [robot_op/extract/](robot_op/extract/) | Извлечение из PDF и сканов, восстановление таблиц и проверки полей |
| [robot_op/models.py](robot_op/models.py) | ОП, документы, JSON-версии, задания и журнал |
| [demo_site/](demo_site/) и [tests/](tests/) | Тестовый сайт, документы и сценарии регрессии |

ИРНИТУ публикует учебный план (УП), календарный учебный график (КУГ), рабочие программы дисциплин (РПД), программы практик, основную образовательную программу (ООП), ГИА и ФОС ГИА. Система находит документы на странице конкретного набора, скачивает PDF, извлекает текст или применяет OCR, проверяет извлечённые данные, сохраняет первичный и итоговый JSON и собирает страницу ОП. [Исходный раздел ИРНИТУ](https://www.istu.edu/sveden/education/).

- Идентичность PDF определяется по SHA-256. Условные HTTP-запросы могут использовать ETag и Last-Modified. При одинаковом документе и версии парсера повторно используется результат разбора. В [pipeline.py](robot_op/robot/pipeline.py) хранится версия парсера и логика обновлений.
- JSON хранится с версиями. Ошибка одного документа должна оставлять работоспособными обработку остальных и отображение уже сохранённых материалов. Для наборов за входом ЕСИА сверяйте реальную доступность PDF и журнал.
- В LLM отправляются структурированные сведения. Если краткое описание отсутствует, уже извлечённые факты доступны на странице. При повторном запуске можно заполнить пропущенное описание без нового разбора PDF.
- Краткая характеристика ОП строится по ООП, в том числе из извлечённых полей при отсутствии результата модели. Текст ГИА берётся из программы ГИА с возможным запасным описанием из ФОС ГИА. В интерфейсе отображается краткий текст, к первоисточнику остаётся ссылка.
- Для оценки качества OCR сравнивайте таблицу и шапку с оригинальным PDF. Особое внимание уделяйте разорванным столбцам семестров, индексам модулей, видам контроля и различию академических часов и пар.

## Каталог и интерфейс

- Каталог открывается на `/programs`, `/run` также показывает список и используется в процессе обработки. Уже сохранённая программа открывается ссылкой. Новая запускается при открытии, её карточка показывает состояние загрузки. Повторное открытие сохранённой карточки и параллельное открытие той же загружаемой программы используют существующую страницу или задачу.
- Сохранённый каталог отрисовывается на сервере. Браузер не запрашивает его заново при обычной перезагрузке или выборе уже открытого набора. Первый запрос нового года добавляет его в список. Поиск по названию, профилю и коду и переключение уровня используют загруженные карточки. Первичная попытка обновления каталога возможна при запуске сервера. При недоступности источника остаётся сохранённый список.
- Фильтры года и уровня учитывают параметры ссылки `year` и `level`. Для проверки кэша отдельно измеряйте сетевой запрос браузера к каталогу, запросы бэкенда к ИРНИТУ и появление новых задач обработки.
- Учебный план растягивается по высоте. На узком экране широкую таблицу можно прокрутить по горизонтали. КУГ и навигация по программе учитывают доступную ширину. Проверяйте широкий и мобильный экран.
- Дисциплины по выбору показываются через «/» с отдельными ссылками на варианты. Факультативы отмечаются отдельно, а недельный итог считается без них. При проверке физкультуры в старших семестрах используйте индекс и блок учебного плана. Для ИСОИУ отдельно проверяйте факультативы в восьмом семестре.
- Если РПД отсутствует, карточка использует сведения из УП и сообщение «Рабочая программа пока не опубликована». Для остальных неполных разделов используется соответствующее сообщение о публикации. При обработке каждой ОП робот берёт преподавателей и дисциплины из [реестра ИРНИТУ](https://www.istu.edu/sveden/employees). Персональные ссылки робот ищет по спискам сотрудников, обнаруженным на страницах институтов, кафедр и факультетов в [структуре ИРНИТУ](https://www.istu.edu/struktura/). При совпадении фамилии и инициалов сверяем дисциплину с карточками и сохраняем все совпавшие ссылки. Если ни одна карточка не содержит дисциплину, выбираем первую найденную. При отсутствии карточки ищем личное расписание. Если его не нашли, имя ведёт на [поиск в расписании ИРНИТУ](https://www.istu.edu/raspisanie/poisk). Проверенные резервные данные хранятся в [config/teacher_profiles.json](config/teacher_profiles.json).
- Переключатель треков находится под кнопками семестров и показывается при нескольких траекториях. Смена трека сохраняет семестр и обновляет дисциплины, практики, нагрузку и ссылки. Общие дисциплины видны в каждом треке. Одноимённые РПД сопоставляются с учебным планом по семестрам, часам и трудоёмкости.

### Проверочный пример ЦППМ

В ОП 09.04.02 «Цифровизация промышленных предприятий», набор 2026, исходный УП содержит «Применение искусственного интеллекта в промышленности» и «Промышленный интернет вещей». Проверены разные дисциплины и практики, разные РПД по машинному и глубокому обучению и общие предметы. Повторное распознавание исправило пропущенные колонки четвёртого семестра. В сверенном PDF у каждого трека по семестрам 105, 91, 91 и 52 пары и 120 з. е. по программе. Программа с одной траекторией является контрольным случаем без переключателя.

## Проверки перед публикацией

Запускайте тесты из корня репозитория. Полный прогон для состояния приложения в коммите `402c0ec` — 229 успешных тестов с одним предупреждением Starlette о совместимости TestClient с httpx. Из них 58 проверок добавлены в последней серии работ по качеству. В браузере использовался Chromium через Playwright.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -q tests/test_catalog_regression.py tests/test_summary_regression.py tests/test_defensive_contracts.py
.venv/bin/python -m pytest -q tests/test_browser.py
```

Для браузерных тестов установите Playwright в окружение и Chromium командой `python -m playwright install chromium`. Без них браузерный набор может быть пропущен. Сценарии используют временную SQLite и имитацию внешних ответов. Для локальной проверки приложения дополнительно откройте сохранённую ОП и РПД, попробуйте поиск, смену года, семестра и трека.

- [Тесты каталога](tests/test_catalog_regression.py) проверяют холодную загрузку, повторное чтение снимка, параллельные запросы, исторический год, сбои источника и одну задачу на программу.
- [Браузерные сценарии](tests/test_browser.py) проверяют число запросов, фильтры, поиск, восстановление после сбоя, выбор семестра, трека и категории, переход к PDF и мобильный статический снимок.
- [Тесты характеристик](tests/test_summary_regression.py) проверяют пустой, ошибочный и нетекстовый ответ LLM, тайм-аут, сохранение разобранных данных и повторное формирование описания. [Тесты ГИА](tests/test_attestation_summary.py) проверяют ограничения кратких текстов.
- [Учебные планы](tests/test_plan_tracks.py), [распознавание сканов](tests/test_ocr_accuracy.py) и [выгрузка Pages](tests/test_export_pages.py) проверяются отдельно.
- [Защитные проверки](tests/test_defensive_contracts.py) покрывают HTTPS, размер скачиваемых документов, параметры Nginx, метаданные выдачи, экранирование и принадлежность документа программе. Проверки ведутся на собственном коде и изолированных данных.

При проверке работающего экземпляра три последовательные перезагрузки каталога дали ноль дополнительных запросов браузера к фрагменту каталога и ноль задач обработки. При новых правках повторите измерение и сравните число записей в БД до и после сценария.

### Открытые вопросы перед серверной публикацией

- Проверять разрешённый адрес и схему для каждого исходящего перенаправления до отправки запроса. Текущая проверка конечного адреса не доказывает проверку каждого перехода. См. [robot_op/robot/http.py](robot_op/robot/http.py).
- Определить доступ к запуску, остановке и возобновлению задач и служебным отчётам. В серверной конфигурации ограничить прямой порт приложения, если вход должен проходить через Nginx. См. [robot_op/web/app.py](robot_op/web/app.py) и [docker-compose.yml](docker-compose.yml).
- Добавить отдельный лимит для HTML-ответов каталога и проверить ограничение выдачи PDF выделенным каталогом. Лимиты скачивания PDF и параметры Nginx уже покрыты защитными тестами.
- Для повторной оценки характеристик сначала уточнить причину пропусков по документу и запуску, затем проверить успешное дополнение итогового JSON без изменения исходных данных. Метрики по охвату хранилища и по вызовам модели имеют разные знаменатели.
